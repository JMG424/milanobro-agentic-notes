The file system

This is the whole design.

Each file answers one question about how the assistant serves Mario. Tap a file to see what it does.

mario-chief-of-staff/

Plain text. Readable by Mario, reviewable by IT.

SOUL.md

How it behaves

The character of the assistant: direct, brief, honest about uncertainty, and never acting on its own.

# Soul Be direct. Match the length of the answer to the weight of the ask. Separate facts from assumptions. Say when you don't know. Draft and recommend first. Nothing is sent, booked or changed without Mario's explicit yes. Keep source receipts for every claim.
For MarioAn assistant that sounds like a good chief of staff, not a chatbot, and that knows the difference between advising and acting.
USER.md

Who Mario is

What the assistant knows about the person it serves. Built up through the onboarding interviews, corrected and approved by Mario.

# Mario Role: President, Milano Brothers Group Languages: Italian, English (reply in the language used) Priorities this quarter: …approved by Mario… Key people: …who matters, and how to address them… Decision style: wants options with a recommendation, not a menu Never: send on my behalf · touch other people's mailboxes
For MarioThis is the file that makes it his assistant. It gets more accurate every week, and he can read and edit every line.
AGENTS.md

How it works

The working loop, written down: what to do with new information and how to hand it back.

# Working loop 1. Read what's new in the approved lanes 2. Sort: decisions needed · waiting on others · noise 3. Draft the reply, the brief, or the action list 4. Show sources beside every claim 5. Stop at the approval gate and wait for Mario
For MarioPredictable output every time: priorities, decisions, owners, due dates, and drafts, clearly separated from guesses.
TOOLS.md

What it may touch

The complete list of what the assistant can reach, and what it can only read. Nothing outside this list.

# Allowed access Outlook (Mario's mailbox) ........ read Calendar (selected) .............. read Drive (selected files only) ...... read Telegram (private, paired) ....... talk to Mario # Blocked until approved per action send · book · change · purchase · publish · delegate
For ITOne page to review. Access is granted inside the company’s own tenant and can be revoked there at any time.
HEARTBEAT.md

Its daily rhythm

The scheduled check-ins, so Mario doesn’t have to remember to ask.

# Rhythm (staged, switched on when Mario is ready) 07:30 Morning brief: decisions waiting, follow-ups, one thing first Before each meeting Prep note: who, history, what was agreed last time 18:00 Closeout: what moved, what's open, tomorrow's first move
For MarioStarts the day with the three things that matter, ends it with nothing forgotten.
skills/

Repeatable work

Each recurring task is written down once as a skill, then done the same way every time.

skills/ ├─ morning-brief/ ├─ meeting-to-actions/ transcript → decisions, owners, dates ├─ draft-follow-up/ reply in Mario's voice, for approval ├─ open-loops/ what was promised, by whom, overdue └─ think-it-through/ options + recommendation, with sources
For MarioNew skills can be added as he finds new uses. Each one is a small, reviewable file, not a new system.
memory/

What it has learned

The context layer. Human-readable notes with sources, plus a search over them. Only what Mario approves is kept.

memory/ ├─ vault/ curated notes: people, decisions, projects (with receipts) ├─ facts.md confirmed facts, rules and preferences └─ index/ search over the vault, on Mario's server # Gate: raw answer → summarised → Mario corrects → approved → kept
For MarioThis is the asset that compounds. It belongs to Milano Bro and works with whichever AI model is best that year.

Where it stands

Built and live. Not yet acting on its own.

Live and verified

  • Private runtime in an isolated cloud environment
  • Chief-of-staff profile and the files above
  • Text and voice-note interface
  • Governed memory with search
  • Read-only lanes: Outlook, Calendar, selected Drive files
  • Self-heal, monitoring and rollback

Deliberately not active

  • No sending or calendar changes on its own
  • No broad mailbox or file indexing
  • No scheduled morning / evening runs yet
  • No regulated or restricted data
  • Onboarding interview not yet completed
  • Mario’s day-to-day use still to be proven
Best next moveOne onboarding session, one low-risk real workflow, Mario corrects the result, and only what he approves is kept.
