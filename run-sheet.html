01The opportunity with agents today

A chatbot answers from what is typed into it. An agent has two things a chatbot does not: prior context about the person and the work, and access to tools such as mail, calendar and files, used only with approval.

Context is the important part. Thin context produces generic answers. A deep, trusted, evolving context of mail, calendar, decisions and operating knowledge is what lets a model behave like someone who lives inside the work. The tools matter less than what the agent already knows.

The opportunity is not a better chatbot. It is a controlled context layer that any current model can use, inside whatever stack IT approves.

02What is needed: a secure context layer

The proposal: a context layer for Mario that is curated, human-readable and searchable, held inside a Milano Bro cloud account with tenant-scoped, narrow Microsoft 365 access, plus a retention, deletion and exit procedure. An assistant on top of it briefs priorities, supports decisions with context, drafts work, and acts only with clear approval.

Does the Milano Bro version already work? Not yet. It has not been built. The demonstrations use Jason’s existing assistant, on Jason’s own data.

Scope. No other employees’ mailboxes. No SharePoint, OneDrive or broad document stores for now. Microsoft 365 access limited to what the pilot needs. Email first; calendar and meetings, Teams, and voice would each be a later phase with its own security implications for Romansas to review.

Copilot, looked at together. Copilot is a reasonable default: mail, calendar, Teams and meetings already live there. The question to look at together is whether it covers the needs of this one personal pilot.

  • Multilingual handling, at the level Mario works in day to day
  • The degree of personalization Mario has described
  • Where a separate, evolving context layer would add something Copilot does not, if anywhere

Which cloud account would host the model and the context layer is IT’s decision.
