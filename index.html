1 · Agents and context

An agent is a harness around a frontier model, with tools and guardrails — not a chatbot bolted onto email.

Usefulness comes from depth of trusted context. Thin context produces generic answers. A secure, evolving context layer — mail, calendar, decisions, operating knowledge — is what lets the model behave like someone who lives inside the work.

North star (from Jason’s 20 Sept note): put Mario in a position where a continuously evolving, controlled context layer can be used with current models — then plug that layer into the enterprise stack IT accepts.

2 · Hermes for Mario

Hermes is the proposed chief-of-staff style agent for Milanobro: brief priorities, support decisions with context, draft work, and execute only with clear approval.

Important distinction for this session: what you will see demonstrated runs on Jason’s infrastructure with test data. The proposed Milanobro deployment (models via Bedrock or Azure OpenAI inside Milanobro’s cloud, scoped Microsoft Graph access) is design — not yet built or IT-approved.

Ask for this session Access to begin a secure, evolving context layer for Mario — starting narrow (revocable). Clear boundary on what may be read. An owner on the Milanobro side for approvals and expansion.

6 · Microsoft comparison (open questions)

Romansas’s frame: start from Microsoft 365 Copilot / Copilot Studio because mail, calendar, Teams, and meetings already live there. Claude does not by itself require AWS. Fair comparison covers capability gap, build effort, run cost, and ongoing support.

  • What can Copilot Studio already do for Mario’s executive-assistant goal?
  • Where does a separate context layer add leverage Copilot does not?
  • What company data would be stored in AWS vs retrieved on demand?
  • AWS Bedrock vs Azure OpenAI — same design idea, different home cloud; IT chooses.

Session posture: demonstrate first; settle architecture after both sides have seen the demos.

7 · Mario’s roadmap (scope)

Comfortable now

No other employees’ mailboxes. No SharePoint / OneDrive / broad document stores for now. Limit Microsoft 365 access to what the pilot needs.

Required for usefulness

Eventually: Mario’s calendar; meetings and transcripts; Teams chats and channels; voice interaction.

Phased path

Phase 1 email → Phase 2 calendar & meetings → Phase 3 Teams → later phases include voice and deeper ops knowledge. Each phase carries its own security implications for Romansas to review.
