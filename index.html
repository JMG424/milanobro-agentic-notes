01Agents and context

An agent is a harness around a frontier model, with tools and guardrails. It is not a chatbot bolted onto email.

Usefulness comes from depth of trusted context. Thin context produces generic answers. A secure, evolving context layer of mail, calendar, decisions and operating knowledge is what lets the model behave like someone who lives inside the work.

North star, from Jason’s 20 Sept note: put Mario in a position where a continuously evolving, controlled context layer can be used with current models, then plug that layer into the enterprise stack IT accepts.

02Hermes for Mario

Hermes is the proposed chief-of-staff style agent for Milanobro: brief priorities, support decisions with context, draft work, and execute only with clear approval.

Important distinction for this session. What you will see demonstrated runs on Jason’s infrastructure with test data. The proposed Milanobro deployment, with models via Bedrock or Azure OpenAI inside Milanobro’s cloud and scoped Microsoft Graph access, is a design. It is not yet built or IT-approved.

Ask for this session Access to begin a secure, evolving context layer for Mario, starting narrow and revocable. A clear boundary on what may be read. An owner on the Milanobro side for approvals and expansion.

06Microsoft comparison (open questions)

Romansas’s frame: start from Microsoft 365 Copilot / Copilot Studio, because mail, calendar, Teams and meetings already live there. Claude does not by itself require AWS. A fair comparison covers capability gap, build effort, run cost and ongoing support.

  • What can Copilot Studio already do for Mario’s executive-assistant goal?
  • Where does a separate context layer add leverage Copilot does not?
  • What company data would be stored in AWS versus retrieved on demand?
  • AWS Bedrock versus Azure OpenAI: same design idea, different home cloud. IT chooses.

Session posture: demonstrate first, settle architecture after both sides have seen the demos.

07Mario’s roadmap (scope)

Comfortable now

No other employees’ mailboxes. No SharePoint, OneDrive or broad document stores for now. Microsoft 365 access limited to what the pilot needs.

Required for usefulness

Eventually: Mario’s calendar; meetings and transcripts; Teams chats and channels; voice interaction.

Phased path

Phase 1 email → Phase 2 calendar and meetings → Phase 3 Teams → later phases add voice and deeper operating knowledge. Each phase carries its own security implications for Romansas to review.
